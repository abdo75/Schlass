## Tasks

1. **B5: AuditPanel modal a11y.**
   - Add `aria-modal="true"` and `aria-labelledby="<id>"` pointing to the title element.
   - On open: capture `document.activeElement` (the row that opened it); on close: restore focus to it.
   - Implement focus trap: Tab/Shift+Tab cycle within the panel; Tab from last element loops to first.
   - Auto-focus the close button on open (first interactive element).
   - ESC handler already present at `:30-36` — keep.
   - Backdrop click already closes — keep, but add `role="presentation"` to the backdrop div if it isn't already.

2. **B5 (cont): StepUpModal a11y.**
   - Add `aria-modal="true"` and `aria-labelledby` to the dialog.
   - Add ESC handler to close (currently missing; only X/Cancel buttons close).
   - Add focus trap (same hook/lib as AuditPanel).
   - **autoFocus** the code input on open (`useEffect` watching `open`, ref-based focus).
   - **M11 partial:** Reorder controls so the recovery toggle is BEFORE the input (keyboard tab order: input → submit, with toggle outside that flow).

3. **M4: AuditTimeline row keyboard-op.** Choose one approach (recommendation: option B):
   - **A.** Convert `<tr onClick>` to row with no native click; render an explicit `<button aria-label="View detail">` in a leading or trailing column. Keyboard users tab to that button.
   - **B.** Keep row clickable for mouse, ALSO make it keyboard-actionable: add `tabIndex={0}`, `role="button"`, `onKeyDown` handler for Enter/Space. Pull the nested action buttons (`button` elements at `:84-122`) OUT of the row so keyboard activation isn't ambiguous — render them in their own column with `e.stopPropagation()` already in place.
   
   Either way: ensure the row has a visible focus ring (use the existing `:focus-visible` ring utility from S01).

4. **M5 (keyboard half): AuditCalendar arrow-nav.**
   - Add a single `onKeyDown` handler on the day-grid container (delegated to `<button>` day cells).
   - ←/→ move by 1 day; ↑/↓ move by 7 days; PgUp/PgDn move by month; Home moves to start of week; End to end of week.
   - Move focus programmatically via refs to the new day's button.
   - Ensure month change happens automatically when nav crosses month boundary.

5. **M7 (ARIA half): AuditTabs proper ARIA.**
   - Tabs container `role="tablist"`, `aria-orientation="horizontal"`.
   - Each tab `role="tab"`, `aria-selected`, `aria-controls="panel-id"`, `tabIndex={isActive ? 0 : -1}` (roving tabindex).
   - Panels rendered with `role="tabpanel"` and matching `id`/`aria-labelledby`.
   - Arrow-key handler on the tablist: ←/→ cycle active tab. Home/End jump to first/last.

6. **M14: Picker popover ARIA.** For each of TimePicker, EventTypePicker, ActorPicker, TargetPicker, ExportMenu:
   - Trigger button: `aria-haspopup="listbox"` (or `dialog` for TimePicker which has internal form), `aria-expanded={open}`, `aria-controls="<popover-id>"`.
   - Popover container: appropriate role (`listbox` for ActorPicker/TargetPicker/EventTypePicker; `dialog` for TimePicker; `menu` for ExportMenu).
   - ESC handler inside popover closes it.
   - Enter key in TimePicker/EventTypePicker submits the form (Apply).
   - Focus management: opening popover focuses first interactive child; closing returns focus to trigger.

7. **Tests:** Add minimal a11y assertions in existing `*.test.tsx`:
   - `AuditPanel.test.tsx`: `expect(getByRole('dialog', { name: /event detail/i })).toHaveAttribute('aria-modal', 'true')`.
   - `StepUpModal.test.tsx`: assert ESC closes; assert input has focus on open.
   - `AuditTabs.test.tsx`: add new test file — assert arrow-key tab cycling, `aria-selected`.
   - `AuditCalendar.test.tsx`: assert ←/→ move focus to neighbor day.
   - Pickers: assert trigger has correct `aria-expanded` on open/close.
