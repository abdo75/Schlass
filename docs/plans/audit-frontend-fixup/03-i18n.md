## Method

1. **Inventory pass.** Open each `.tsx` file in scope. For every JSX text child, every `aria-label`, every `placeholder`, every `title` attribute, every label inside a `const X_LABELS = { … }` map — note its current English string.

2. **Key naming.** Use the existing `audit.*` namespace. Follow established sub-namespaces:
   - `audit.timeline.*` — table headers, empty state, GDPR badge
   - `audit.tabs.*` — tab labels
   - `audit.refine.*` — filter bar (already has 5 keys; extend)
   - `audit.timepicker.*` — preset labels, "Custom range", "Apply"
   - `audit.calendar.*` — `previousMonth`, `nextMonth`, `pickStart`, `pickEnd` (only aria-labels; month/weekday names come from `Intl`)
   - `audit.eventTypePicker.*` — "{{count}} selected", "Clear", "Apply"
   - `audit.actorPicker.*` — "Search actors", "System", "No actors found."
   - `audit.targetPicker.*` — "Back", "Search targets", "No targets found.", `aria-label="Target type"`, all `TYPE_LABELS` entries
   - `audit.export.*` — format labels, "Export", manifest hint
   - `audit.panel.*` — close, eventDetail, copy/export aria, `humanizeTargetType` map
   - `audit.target.*` — `targetLabelFor` map
   - `audit.module.*` — AuditPanelModules headings ("Changed fields", "Reset tokens", etc.)
   - `audit.error.*` — already has `.fetch` and `.retry`; ADD `.unexpected`
   - `audit.stepup.*` — already has keys; ADD `unexpected_error`, `recovery_label` (separate from existing `recovery_link`)
   - `audit.loading` — single key, replaces `"Loading..."`
   - `settings.audit.*` — `AuditLogTab` strings

3. **Wrap in `t(...)`.** Each `.tsx` change is straightforward: add `const { t } = useTranslation()` if not already; replace literal with `{t("audit.x.y")}` or `aria-label={t("audit.x.y")}`. For interpolated strings (e.g. `"{{count}} selected"`), use t with options: `t("audit.eventTypePicker.countSelected", { count })`.

4. **Migrate label-maps.** For const maps like `TYPE_LABELS`, `FORMAT_LABELS`: convert into a function `getTypeLabel(t, type)` that returns `t("audit.targetPicker.typeLabels." + type)`, OR keep the map keyed by the type but make values be i18n keys, then call `t(map[type])` at render. Pick whichever reads cleaner; both work.

5. **AuditCalendar locale-aware names.**
   - Replace hardcoded `MONTHS = ["January", …]` with `new Intl.DateTimeFormat(i18n.language, { month: "long" }).format(date)`.
   - Replace `["M","T","W","T","F","S","S"]` with `new Intl.DateTimeFormat(i18n.language, { weekday: "narrow" }).format(date)` for each weekday position. Cache per render via `useMemo` keyed on `i18n.language`.

6. **Populate fr.json + de.json.** For every new key added in S03, plus the 25 keys from B3 already missing, add a real translation. Use the existing translation tone in those files (formal "Sie" in de, formal "vous" in fr). For key UI strings:
   - "Search actors" → fr: "Rechercher des acteurs" / de: "Akteure suchen"
   - "No actors found." → fr: "Aucun acteur trouvé." / de: "Keine Akteure gefunden."
   - "Apply" → fr: "Appliquer" / de: "Anwenden"
   - "Last hour" → fr: "Dernière heure" / de: "Letzte Stunde"
   - "Custom range" → fr: "Plage personnalisée" / de: "Benutzerdefinierter Zeitraum"
   - "Changed fields" → fr: "Champs modifiés" / de: "Geänderte Felder"
   - …(maintain consistency with sibling translations already in those files)

7. **Verify parity.** Add a quick assertion script (one-off `node` snippet, or a small vitest like `i18n-parity.test.ts`) confirming every key in `en.json` exists in `fr.json` AND `de.json`. Recommended: write a test file `web/src/i18n/__tests__/parity.test.ts`:
   ```ts
   import en from '../locales/en.json'; // etc.
   const allKeys = (obj, prefix = '') => Object.entries(obj).flatMap(([k, v]) => typeof v === 'object' && v ? allKeys(v, `${prefix}${k}.`) : [`${prefix}${k}`]);
   const enKeys = new Set(allKeys(en));
   ['fr', 'de'].forEach(loc => { const keys = new Set(allKeys(localeMap[loc])); enKeys.forEach(k => expect(keys.has(k)).toBe(true)); });
   ```
   This guard prevents future regressions.
